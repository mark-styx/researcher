# Research quality bake-off, 2026-09-25

Phase 4 of `~/sentinel/research-stack-convergence-plan.md`: compare bookworm's
researcher with researchguy's hybrid inquiry dive on the same research briefs,
before deciding whether bookworm should use researchguy for research.

## Result

Keep bookworm's researcher. Neither researchguy arm passes the decision rule's
cost and time gate, so the hand-reviewed supported-claim rate cannot change
the outcome:

- **C (hybrid inquiry, Claude workers)** cost $7.46 and 30 minutes for one
  topic. Arm A cost $0.86 and 4 minutes for the same topic, so C is 8.7x the
  cost; the rule allowed 2x. The six books ran 28-67 research topics each, so
  C would cost ~$210-500 per book against ~$35-80 for A (at A's $1.20 average).
- **B (hybrid inquiry, local ollama workers)** did not finish one topic. It was
  stopped after 1h42m with 59 tool calls made and no report written.
  `qwen3-coder-next` does not support prompt caching in ollama 0.17.7 ("model
  does not support caching" in the ollama log), so every tool-loop step
  re-reads the whole growing context: chat calls went from 35s to 29m.
- Both arms produce real links. A: 100 unique URLs over three topics, 81% load,
  19% bot-blocked (SAGE, Science, JAMA, PNAS), 0 dead. C: 22 URLs, 82% load,
  0 dead.
- C found more limiting and disconfirming statements on the shared topic (12
  sentences against A's 6), and its narrative-vs-evidence critic caught a real
  error: the executive summary asserted a contamination effect that section 4
  of the same report says no study isolates. That critic is the part worth
  keeping. It runs as a single sonnet call ($0.39 here), which is Phase 8
  (critics on chapters), not a reason to swap researchers.

The blinded claim sheet (`bakeoff-2026-09-25/review.md`, 39 claims) is ready
if you want an absolute sourcing check on bookworm's researcher, but it is
optional for this decision.

## Remediation status, 2026-10-01

The default local pipeline now addresses the resource and critic failures this
bake-off exposed:

- `glm-4.7-flash` is the single worker, `qwen3.8:27b-q4_K_M` is the
  aggregator, and `qwen3.5:9b` handles utility work and optional verification.
- Ollama requests cap context at 32,768 tokens and output at 4,096 tokens,
  retain models only across one tool loop, and unload between hybrid stages.
- Named modes cover every role by default. `inquiry` now runs all five roles
  unless `--branches` explicitly narrows it.
- Successful tool results form a separate evidence ledger. Groundedness is
  flag-only and cannot rewrite the draft; verification remains off by default.
- Tool loops default to six iterations and six search results, with one hybrid
  stage running at a time.

These are implementation changes, not new benchmark results. The replacement
stack still needs a fresh bake-off before it can supersede the result above.

## Findings

**1. Headless Claude calls consult researchguy on their own.** The first arm A
run was contaminated. In all three topics bookworm's researcher called
`researchguy_context` and `researchguy_search`, then used Bash and Read to
open *The Poisoned Well*'s finished research for the same section. It made 3-4
web searches per topic, against 17-34 once isolated. Two things combine: the
researchguy MCP server is registered at user scope (Phase 1), and the global
`~/.claude/CLAUDE.md` tells every session to check researchguy before
researching. Every `claude -p` call on this machine inherits both: bookworm's
researcher, researchguy's own Claude workers (C's workers called it too, and
got an error only because the bake-off config has no grepai project), and
alo's agents. Unlike Phase 2's prior-research path, this one has no exclusion
for the book's own files and no instruction to re-verify. Suggested fix:
`--strict-mcp-config` in bookworm's and researchguy's Claude backends, so a
call only gets the MCP servers it was given. Not done here.

**2. `--allowedTools` is not a boundary in headless auto mode.** C's opus
aggregator was given no tools, yet ran 8 turns with 1 web search and 5 page
fetches, and labeled the result a "targeted verification pass". This matches
the finding that headless sonnet and opus inherit `defaultMode: auto`.

**3. The groundedness critic deletes true facts.** Its rule is to keep only
claims found in the worker drafts, so facts the aggregator added from its own
lookups get cut even when correct. Four of its removals, checked against
Wikipedia, were accurate: Stasi Directive No. 1/76, John Marks obtaining CIA
documents under FOIA, Pizzagate tweets coming disproportionately from the
Czech Republic, Cyprus, and Vietnam, and Project Mockingbird's place in the
Family Jewels. The narrative critic likewise flagged three accurate dates as
"unsourced precision" (Robertson Panel in January 1953, U-2 first flight in
1955, the March 1968 COINTELPRO directive). All 17 flags are real by the
critics' own definition of "not in the worker drafts"; the groundedness
removals mostly cost accuracy, while the narrative critic's catch of the
summary-vs-section-4 contradiction is a genuine error neither arm would
otherwise surface.

**4. `--mode inquiry` runs 2 of its 5 angles by default.** The branch count
defaults to the number of worker models (2), so without `--branches 5` inquiry
mode covers only "primary evidence" and "counter-evidence". This run used
`--branches 5`.

**5. bookworm's per-topic source target is the floor of 3.** *The Poisoned
Well*'s researchers had 6-13 topics each, so `20 / n` was at most 3 and every
prompt asked for "3 or more" sources. The researcher cited 30-35 URLs per topic anyway.

**6. Dive reports repeat the whole brief as their title.** researchguy writes
`# <topic>` at the top of a dive, and here the topic was a 3KB brief.
Harmless for short topics, noisy for briefs.

## Deviations from the plan

- `--branches 5` for B and C instead of the default, per finding 4.
- C ran on one topic, not three: at ~$7.50 per topic it failed the cost gate
  after the first, and two more topics could not change the decision.
- B was stopped before finishing, so it has no quality numbers.
- Arm A ran with local file tools denied (`--disallowedTools Bash Read Glob
  Grep`) and a scratch researchguy config, to undo the contamination in
  finding 1. Those tools have no legitimate use in a scratch book with no
  provided materials. Transcripts of the rerun show no local file access.
- The supported-claim review is left to hand review, as the plan intended,
  and does not block the decision.

## Setup

**Topics.** Three sections of *The Poisoned Well*'s research plan
(`~/sentinel/books/the_poisoned_well/research/research-plan.md`), used verbatim
as the brief for every arm. The `###` header was demoted to `##` so bookworm
treats each file as exactly one topic.

| Topic | Section | Kind |
|---|---|---|
| t1 | 1.2 Seeding Unhinged Versions: The Discrediting Operation | contested history (COINTELPRO, Mockingbird, limited hangout, Pizzagate) |
| t2 | 2.3 The Replication Crisis as Diagnostic Evidence | science, well-documented numbers |
| t3 | 3.1 The Mechanics of Thought Reform | psychology and history (Lifton, Hassan, Singer) |

**Arms.**

| Arm | Command | Models |
|---|---|---|
| A | `bookworm research` in a scratch book with The Poisoned Well's `bookworm.yaml`, 1 researcher, `max_sources_per_researcher: 3` | Claude sonnet with WebSearch and WebFetch |
| B | `researchguy dive --backend hybrid --mode inquiry --branches 5 --no-research --out ... --json` | workers: ollama `qwen3-coder-next` and `nemotron` (DuckDuckGo search, fetch); aggregator: Claude opus; critics: Claude sonnet |
| C | same as B | workers: Claude sonnet with WebSearch and WebFetch; aggregator and critics as B |

All arms start from scratch. researchguy prior research is off in A (its
default) and `--no-research` is set for B and C, because the topics come from
a finished book whose research is already in the researchguy corpus.

`max_sources_per_researcher: 3` reproduces the production prompt. The real
Poisoned Well run split each researcher's assignment into 6-13 topics, so
`20 / n` was at most 3 and every topic prompt said "Aim for 3 or more
distinct sources". With one topic per researcher the default of 20 would have
asked this run for 20, which production never did.

**Measurement.** `go run ./tools/bakeoff` (this repo) reads the outputs:

- Unique URLs: every http(s) URL in the output, normalized with
  `graph.NormalizeURL`, counted once.
- URL resolution: HEAD, then GET on failure, 20s timeout, browser user agent.
  `ok` is a final 2xx/3xx; `blocked` is 401/403/429 (the page may exist but
  refuses automated clients); `dead` is 404/410 or a host that does not
  resolve; `error` is everything else.
- Counter-evidence, two ways. "Headed" counts items under headings that
  announce counter-evidence, criticism, or limitations. "Limiting sentences"
  counts sentences with disconfirming language ("no evidence", "not
  documented", "failed to replicate", "disputed") anywhere in the body, so it
  does not depend on how an arm structures its report. Both are heuristics.
- Critic flags: list items under the hybrid backend's `## Critic Notes`.
- Cost: a wrapper named `claude` first on `PATH` ran the real CLI with
  `--output-format json` and logged `total_cost_usd` (list price) per call,
  then printed the plain text back, so neither tool's code changed. Ollama
  compute is not priced. Each call had a `--max-budget-usd 3` cap.
- Supported claims: `bakeoff sample` draws 20 attributed sentences per arm,
  spread across topics, shuffles them together, and writes a blinded sheet
  (`bakeoff-2026-09-25/review.md`) plus a key. Attributed means the sentence
  carries a URL, a markdown link, a `[n]` reference, or a parenthetical year.
  Citations are resolved to the output's own source list.
